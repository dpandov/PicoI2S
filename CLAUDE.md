# CLAUDE.md

Guidance for Claude Code when working in this repository.

## Project

USB to S/PDIF (Toslink) bridge firmware for the Raspberry Pi Pico 2 (RP2350).
Full design and hardware notes are in `README.md`; read it first. Key points:

- USB Audio Class 2.0, asynchronous mode with feedback endpoint. The Pico is
  the clock master. Never resample.
- UAC1 mode (selected by a pin at boot, see step 7) is adaptive like the
  PCM2704: the S/PDIF clock follows the host through a small fractional
  trim of the PIO divider. Samples stay bit-exact; no resampling there
  either.
- Supported: 32 / 44.1 / 48 / 88.2 / 96 kHz, 16 and 24 bit, stereo
  (UAC1 mode: 32 / 44.1 / 48 kHz, 16 bit).
- S/PDIF is generated by PIO (biphase-mark), fed by DMA from a CPU-built
  subframe double buffer.
- The system PLL is switched per sample-rate family so the PIO divider is an
  integer (see the table in `README.md`). Keep the UART on the 48 MHz USB PLL
  so logging survives a clock switch.
- Functional requirement (implement in step 3): when audio stops (host
  closes the stream or stops sending samples), transmit S/PDIF silence for
  3 seconds, then stop the S/PDIF output entirely (line idle, no carrier).
  Restart on the next stream. "Audio" = stream open with samples arriving;
  digital silence inside an open stream is still audio.
- LED (GPIO 25): on while audio is playing, off otherwise, plus two short
  flashes on enumeration (two). No other blink patterns.
- Pins: S/PDIF data on GPIO 28 (`SPDIF_PIN`), chosen for proximity to 3V3
  and GND. The onboard LED (GPIO 25) is reserved as the audio/LOCK
  indicator; do not use it for anything else. UART0 on GPIO 0/1 is the console.
  GPIO 5 (`UAC_MODE_PIN`, pin 7 next to GND on pin 8) selects UAC1 when
  grounded at boot.

## Toolchain

- Pico SDK 2.x, ARM GCC, CMake, Ninja, picotool. Installed via the
  Raspberry Pi Pico VS Code extension into `~/.pico-sdk`.
- TinyUSB 0.21.0 is the git submodule `lib/tinyusb`, pinned to the release
  tag and passed to the SDK as `PICO_TINYUSB_PATH` (top of
  `CMakeLists.txt`); the SDK's bundled copy (0.18) is not used. After
  cloning: `git submodule update --init`.
- Board: `PICO_BOARD=pico2`. ARM cores (not RISC-V). Language: C.
- Build: `cmake -S . -B build -G Ninja -DPICO_BOARD=pico2 && cmake --build build`
  (`build/` is the directory the VS Code extension uses; Claude's own
  verification builds go in `scratch/`).
- Command-line builds outside the VS Code terminal need the extension's
  tools on PATH. Versions are pinned at the top of `CMakeLists.txt`. In
  Git Bash:
  `P=~/.pico-sdk; export PICO_SDK_PATH=$P/sdk/<ver> PICO_TOOLCHAIN_PATH=$P/toolchain/<ver> PATH=$P/toolchain/<ver>/bin:$P/picotool/<ver>/picotool:$P/cmake/<ver>/bin:$P/ninja/<ver>:$PATH`
- Flash without BOOTSEL (firmware has the picotool reset interface):
  `picotool load -x <uf2> -f --vid 0x1209 --pid 0x0001`. picotool lives in
  `~/.pico-sdk/picotool/<ver>/picotool/`. BOOTSEL is only needed if the
  firmware is hung with the watchdog disabled, or after flashing other code.
- The Pico's USB port is the audio device, so console output goes to UART0
  (GPIO0/1, 921600 baud), not USB CDC. No debug probe or UART adapter is
  connected yet: use the diagnostic string instead (`tools/diag.py`, see
  `src/diag/diag.h`). It reports panics, hard faults and main-loop hangs from the
  previous boot plus live stream status.
- Windows test tooling: `tools/stream_test.py` (WASAPI exclusive sweep with
  device-side verification). Keep its Python venv in `scratch/venv`.

## Scratch folder rule

All experiments, test programs, throwaway builds, captured data, and
generated analysis go in `scratch/` at the repository root. This folder and
`temp/` are gitignored and must stay that way.

- Any test, probe, or spike Claude writes is created and run from `scratch/`,
  never from the source tree.
- `scratch/` may be deleted at any time; nothing in it is part of the project.
- If something from `scratch/` proves useful, it is rewritten properly into
  the source tree in a separate step, not moved.
- Do not add build directories or scratch content to git. Check `git status`
  before committing.

## Conventions

- Source layout, one folder per subsystem:
  - `src/main.c`: init and main loop only. `src/board_config.h`: pins.
  - `src/usb/`: descriptors, UAC2 class callbacks, `tusb_config.h`. All
    `tud_*` callbacks live here.
  - `src/app/`: application behaviour (audio pipeline, status LED,
    console and diagnostic status line).
  - `src/diag/`: crash and hang diagnostics.
  - `src/spdif/`: S/PDIF transmitter (PIO program, DMA, subframe builder).
  - `src/clock/`: sample-rate-family PLL switching.
  - `tools/`: host-side scripts.
- Includes are relative to `src/` (`#include "usb/usb_audio.h"`).
- Do not mix TinyUSB callbacks with PIO/DMA code.
- Prefer integer arithmetic in the audio path. No floating point in
  interrupt handlers.
- Comments: concise and to the point. Comment only where the code does not
  speak for itself, or where something is important or ambiguous (e.g. the
  reason for a PLL value or a channel-status bit). No planning, development
  stage or history notes in code; those belong in commits and this file.
- Commit messages: short imperative subject, body explaining why.

## Development plan

1. Toolchain install, CMake skeleton, blink, UART logging. (done)
2. UAC2 descriptors from the TinyUSB `uac2_speaker_fb` example. Goal: device
   enumerates on Windows and Linux with the right rates and formats. (done on
   Windows; Linux not yet tested)
3. Phase A: S/PDIF transmitter module (`src/spdif/`), brought up with the
   test tone at 48 kHz. Verify lock on the receiver. (done)
   - BMC encoding on the CPU (table lookup, line-level tracking; preambles
     are constants thanks to even parity). PIO program is `out pins, 1` at
     the cell rate (128 x Fs).
   - clk_sys 147.43 MHz (PLL 12 MHz x 86 / 7 / 1) for the 48 kHz family,
     so the PIO divider is an integer (36 / 24 / 12). 44.1 kHz family comes
     in phase B.
   - Two chained DMA channels over two 96-frame buffers; the completion IRQ
     re-encodes the finished buffer. Frame counter mod 192 drives the block
     preamble and channel status.
   - Channel status: consumer, PCM, copy permitted, category general, no
     pre-emphasis, rate code and word length from the stream format.
     V = U = 0.
   - API: `spdif_tx_init(pin)`, `spdif_tx_start(rate, bits)`,
     `spdif_tx_stop()`, source callback delivering 32-bit left-justified
     stereo samples; silence when the source has none. Stopped = pin low.
   - Test tone: permanent CMake option `USB2SPDIF_TEST_TONE` (default OFF):
     1 kHz at -18 dBFS, both channels, 48 kHz / 24-bit, no host needed.
     Integer table (48 samples per period), no floating point at runtime.
   - Receiver available has a lock indicator only (no rate display). If it
     does not lock, verify with a scratch-only PIO self-check: a second SM
     reads the pin back and decodes it; results go to the diagnostic string.
4. Phase B: replace the audio sink with the S/PDIF pipeline, 3-second
   silence-then-stop (timer starts on stream close or on a stall: stream
   open but no samples arriving), PLL family switch for 44.1 / 88.2 kHz,
   channel status per rate and word length. (done: bit-exact on the line
   at all rates and depths, receiver lock verified with Windows and iPad)
   - Data path: the main loop moves PCM from the TinyUSB FIFO into a small
     ring of 32-bit frames (topped up to a fixed target); the DMA IRQ
     drains the ring. The IRQ must never read the TinyUSB FIFO: the driver
     clears it before calling the close callback.
   - One stop rule: output stops 3 s after the last stream sample entered
     the ring. Covers both stream close and stall.
   - Stream start: pre-roll until the FIFO holds its half-full set point
     plus what the start pulls out (ring target and two DMA buffers), so
     the stream starts with steady-state buffering; then start the output (switching
     the PLL family first if needed). Same rate, other word length: update
     the channel status in place. Other rate: stop, switch, restart.
   - Verification without a receiver: a scratch-only build of the real
     firmware decodes the pin on core 1 (a second PIO SM samples it) while
     the PC plays a test pattern; injected with `ld --wrap`, no hooks in
     `src/`.
5. (merged into phase B)
6. Robustness (underrun / overrun), long-run soak test. (done except the
   long soak, which runs after step 7)
   - Late S/PDIF DMA interrupt (> 1 buffer): detect, recover, count.
   - Main-loop latency: TinyUSB re-arms the ISO OUT endpoint from the main
     loop, so a stall of ~1 ms at 96 kHz loses a packet. Measure the worst
     case, report it; UART logging becomes non-blocking.
   - Pre-roll with real headroom at stream start (24-bit at 96 kHz starts
     with ~4 ms today).
   - USB FIFO overrun detection and count. Per-stream counters (underruns,
     overruns, min ring level, max FIFO level, recoveries) in the
     diagnostic string.
   - Self-test as a public feature: CMake option `USB2SPDIF_SELFTEST`
     (default OFF) decodes the output on core 1 via a second PIO SM and
     reports to the diagnostic string; host tool in `tools/` plays a test
     pattern with a native WASAPI exclusive player (PortAudio is not
     bit-exact) and checks it bit-exact.
   - Soak: short soak (10 min each at 96/24 and 44.1/16, zero glitches)
     before committing this phase; the long soak runs after step 7.
     Stress: rapid format changes, open/close loops, replug, host
     sleep/resume, host CPU load.
   - Hosts: Android (functional: plays, lock, LED, 3-s stop; Eversolo T8
     played 2 h clean on the phase-4 firmware). Linux and macOS later.
7. UAC1 mode selected by a configuration pin at boot. Target: TVs and old
   Windows (PCM2704-style compatibility). (done and verified on Windows 11
   in both modes; iPad (UAC2 Apple feedback path), TV and the long soak
   pending)
   - Upgrade TinyUSB to 0.21 (UAC1 device support since 0.20; ISO
     transfers handled in the ISR since 0.19, which removes the main-loop
     re-arm latency risk), as a git submodule pinned to the release tag
     and passed as `PICO_TINYUSB_PATH`. Port the UAC2 code to the 0.19+
     API and re-verify every 0.18 workaround below.
   - Pin: GP5 (physical pin 7, next to GND on pin 8), internal pull-up,
     read once before `tusb_init()`. High (open) = UAC2, grounded = UAC1.
     No switching at runtime. UAC1 has its own USB PID (Windows caches the
     driver binding per VID/PID). (done: `main.c`, `usb_audio_mode()`)
   - UAC1 descriptors like the PCM2704: one 16-bit stereo alt setting,
     32 / 44.1 / 48 kHz (Format Type I, discrete), adaptive ISO OUT
     endpoint, no feedback endpoint. Rate via endpoint SET_CUR
     (`tud_audio_set_req_ep_cb()`). (done: device class 0 without IAD, PID
     0x0002, product "USB to S/PDIF (UAC1)", no Feature Unit, S/PDIF output
     terminal, EP 196 bytes; the reset interface and BOS / MS OS 2.0 stay.
     GET_CUR answered, other EP requests STALLed. 48 kHz until the host
     sets a rate, reset on every enumeration. UAC2 descriptors unchanged
     byte for byte.)
   - Adaptive clock: the PLL family and integer PIO divider stay as in
     UAC2; a control loop on the USB FIFO level trims the PIO divider's
     8-bit fraction (dithered between adjacent values for finer average
     resolution). The trim stays within a few hundred ppm, so the
     fraction sits near 0 or 256 and the added jitter is rare single
     clk_sys stretches. (done: `app/clock_servo.c`, `spdif_tx_set_trim_ppb()`.
     The pipeline starts the servo in `begin_playing()`, seeded with minus
     the PLL error on a fresh output, or resumed with
     `clock_servo_resume()` on a running one (warm: same rate and locked
     within the last 2 s, so no re-acquisition swing), and updates it only
     while playing; the trim is held through
     underruns and the silence tail. The UAC1 pre-roll leaves out the DMA
     buffers when the output is running, so a restart begins inside the
     servo's reference window. UAC2 never sets a trim.)
   - Rate after the stream opens: UAC1 hosts select alt 1, then send the
     rate. The pipeline treats a rate change on an open stream as a new
     stream (stop, switch, restart); the pre-roll (about 30 ms of data)
     cannot finish before the rate arrives unless the host streams at the
     old rate first, which then costs one extra restart.
   - Diagnostic string: `1` in place of the Apple flag, `tr<ppm><L|U>`
     (trim, servo lock) appended, counters capped at 99999 in UAC1 mode.
     Tools detect the mode from it and accept PID 0x0002.
   - Then the long soak.

## Known TinyUSB issues (0.21.0)

- The ISO receive path runs in the USB interrupt (`xfer_isr`): FIFO write,
  endpoint re-arm, FIFO_COUNT feedback update and
  `tud_audio_rx_done_isr()`. The 0.18 pre/post read callbacks are gone.
  State shared with that callback needs interrupt-safe access from the main
  loop. A main-loop stall no longer loses packets while the FIFO has room.
- UAC2 feedback is always sent as 16.16 in 4 bytes (the format correction
  callback was removed; only UAC1 gets 10.14 in 3 bytes). For Apple hosts
  `usb_audio.c` rewrites the feedback transfer to 10.14 in 3 bytes
  (`--wrap=usbd_edpt_xfer` in `CMakeLists.txt`). Keep that workaround.
- UAC1 endpoint classification (`audiod_open()` / SET_INTERFACE): a data
  endpoint declared without a sync type is taken for a feedback endpoint.
  The UAC1 data endpoint is adaptive (0x09).
- A zero-length ISO OUT packet still stops reception until the next
  SET_INTERFACE (`audiod_rx_xfer_isr()` returns at
  `TU_VERIFY(0 < tu_fifo_write_n(...))` before the re-arm, without calling
  `tud_audio_rx_done_isr()`). Spec-compliant hosts do not send them;
  `usb_audio.c` sees the idle endpoint from the main loop and counts one bad
  packet per stream.
- Feedback parameters are only read at SET_INTERFACE, not on a UAC2
  sample-rate change while streaming (UAC1 re-reads them on the endpoint
  SET_CUR).
- The feedback clamp is whole samples per ms: floor((fs-1)/1000) to
  fs/1000+1. For the 44.1 kHz family that allows only -0.23 % below nominal
  (44.0 of 44.1), so the S/PDIF clock may run slow by at most ~2000 ppm.
  The planned PLL error (-344 ppm) is inside that.
- `tud_umount_cb()` is called on unplug but not on a bus reset;
  `usb_audio.c` polls `tud_mounted()`.
- Fixed since 0.18 (workaround removed, to be confirmed on hardware with
  open/close loops and direct 16/24-bit switches): on RP2 the audio driver
  uses `usbd_edpt_iso_alloc()` / `usbd_edpt_iso_activate()`, and activate
  aborts a pending transfer, so reopening a stream no longer panics
  ("ep 01 was already available"; a regression would now read
  "buf_ctrl ... already available" in the diagnostic string).
- On RP2350 the USB interrupt handler runs from flash (0.18 put it in RAM as
  part of the RP2040-E15 workaround, which 0.21 applies to RP2040 only). The
  S/PDIF DMA interrupt has higher priority and stays in RAM.

## Host compatibility

- Full Speed feedback format differs per OS: Windows requires a 4-byte EP
  with 16.16 (Code 10 with 3 bytes); Apple requires 3 bytes, 10.14.
  `usb_descriptors.c` detects Apple hosts (string request before config
  request after the device descriptor) and serves a second configuration;
  `usb_audio.c` sends the feedback value in the matching format.
  The diagnostic string shows the guess (`a` / `o`).
- PortAudio's WASAPI exclusive mode (used by `sounddevice`) is not
  bit-exact: it keeps replaying one stale half of its buffer (624-frame
  chunks at 48 kHz). A 1 kHz tone hides this, so `tools/stream_test.py`
  still works, but bit-exact tests must use a native WASAPI exclusive
  (event-driven) player, which delivers the samples unchanged.
- To prove a host follows the feedback, temporarily make the output consume
  a few thousand ppm fast or slow in a scratch build (e.g. a fractional
  PIO divider): the FIFO must stay stable with no underruns. Do not commit such test code.
